# 帖子详情与个人主页收藏修订设计

## 目标

一次性修复帖子详情的商城表情、标签、关注标识和楼中楼 `@` 规则，并完善个人主页收藏夹与点赞模块。

## 设计

- 商城表情：评论媒体组件把商城表情渲染为点击型 `el-popover`。气泡先显示 128px 表情预览，再异步加载所属表情包封面和名称；只有点击所属表情包区域才跳转商城详情。
- 标签：详情页只消费帖子详情接口的 `tags`，用独立响应式状态渲染；超过两个时沿用现有折叠逻辑。
- 关注标识：帖子作者区域不渲染“你的关注”，不改关注关系接口和其他页面。
- 楼中楼：是否显示 `@` 只依据被回复用户是否为帖子作者。回复帖子作者不显示，回复任何其他用户都显示。
- 收藏夹分页：保留 `/favorite/folder/myList` 与 `/favorite/folder/userList` 路径，增加 `pageNum/pageSize`，统一返回 `PageResult<FolderVO>`；个人主页固定请求每页 5 个。
- 收藏帖子摘要：`FolderArticleVO` 不再直接暴露 `Article` Entity，改为专用帖子摘要 VO。标题、去 HTML 后的正文摘要、作者昵称均由 converter 截断；昵称最多 10 个 Unicode 码点，标题和正文使用固定后端上限。作者头像、会员等级和到期时间通过 `UserBriefVO` 返回。
- 收藏界面：收藏帖子右侧第一行显示带会员环头像与昵称，第二行显示赞/评/藏；名称保存按钮改为绿色小勾并在提交期间禁用。
- 点赞模块：复用点赞分页响应的 `total`，切换到点赞页后显示“共点赞 N 个帖子”。

## 错误与状态

- 收藏夹列表保留加载、错误、空数据状态；分页失败时清空当前页并显示错误文案。
- 表情包详情加载失败时气泡仍保留表情预览，并显示加载失败文案。
- 收藏夹改名提交期间禁止重复点击。

## 验证

- 前端 Node 契约测试覆盖 7 项要求并先红后绿。
- 后端单元测试覆盖收藏夹分页及摘要截断。
- 使用 IDEA 自带 Maven 执行相关测试和 `clean compile`。
- 执行 `npm run build`，检查生产代码无 `console.log`。
- 签发短时一次性票据登录，冒烟检查帖子详情与个人主页收藏/点赞模块；不执行购买、发帖、评论等业务写操作。
