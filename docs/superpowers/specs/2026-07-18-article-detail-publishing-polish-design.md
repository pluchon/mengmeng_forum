# 帖子详情与发布流程优化设计

## 目标

在不新增数据表、字段和业务接口的前提下，统一帖子详情评论区、AI 导读、标签、收藏、商城表情与封面发布流程，并将帖子审核结果通知收敛为站内信与 WebSocket。

## 交互设计

- 详情页底部操作仅保留点赞、收藏和分享，评论总数由正文下方标题统一展示。
- 评论编辑器采用“图片按钮 / 输入框 / 发送按钮”单行结构；表情入口仍在输入框后缀中。
- 标签默认展示前两个，其余标签由“展开 +N”控制；展开后完整展示，并可收起。
- AI 导读使用淡红边框和左侧强调线；短正文直接显示“内容过少，无法生成摘要”。
- 视频播放按钮保留语义和键盘能力，但视觉上只显示播放或暂停图标。
- 商城表情点击后先打开气泡：上方放大当前表情，下方展示所属表情包封面和名称；只有点击表情包信息才进入商城详情。
- 楼中楼回复一级评论时不显示“回复 @昵称”，回复另一条楼中楼时才显示目标昵称。
- 收藏弹窗标题为“添加到收藏夹”，只保留整行红色确定按钮。
- 封面页按钮改为“保存为草稿”和“发布”；发布确认框无右上角关闭按钮，取消与确定各占一半。
- 发布提交成功后直接返回首页，提示“审核结果可以在消息中心查看”。

## 审核通知边界

- 前端提交审核只发送 `articleId`，不再询问或传递邮件通知选项。
- 后端审核提交不再接收 `notifyEmail`，审核完成只写系统消息并推送 WebSocket。
- 保留 `MailUtil` 和其他邮件业务，不删除数据库历史字段，不新增迁移。

## 组件边界

- `ArticleDetail`：详情数据编排、标签折叠、评论编辑器与收藏弹窗。
- `CommentReplyMediaDisplay`：区分普通图片和商城表情。
- `CommentShopEmojiPopover`：按 `shopId` 加载气泡所需的封面与名称，并发出跳转事件。
- `SubReplyArea`：加载楼中楼并根据一级评论作者判断是否展示回复目标。
- `ArticleCoverSetup`：封面保存、发布确认和跳转。
- `useArticleAuditSubmit`：单次提交审核与统一成功提示。

## 验证

- Node 源码契约测试覆盖 12 项文案、布局和调用链约束。
- 浏览器验证详情页、收藏弹窗、表情气泡与封面发布确认框。
- 前端执行全量 Node 测试与 `npm run build`。
- 后端执行相关测试及 Maven compile；IDEA Maven 编译由用户侧最终确认。
