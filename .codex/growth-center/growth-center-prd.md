# 成长中心 PRD（P0 已完成 / P1 简化成长体系）

## 1. 文档定位

成长中心是萌部落的用户资格、会员体验与长期成长入口。

它复用现有题库能力作为挑战答题引擎，但不再以“考试题库”作为用户侧产品定位。题库负责出题、答题与进度；成长中心负责定义挑战、判定通过、授予身份或体验权益、记录成长经验。

本 PRD 是当前已确认的需求基线。问答、学习路径、项目共创、知识地图及其他未来方向不在本期范围。

## 2. P0 目标

1. 通过新人试炼区分非正式用户与正式用户，收紧社区内容与社交写入入口。
2. 通过会员体验挑战，为用户提供一次 7 天的 900 积分档会员体验。
3. 提供只展示的成长等级与经验条，为后续成长玩法保留稳定基础。
4. 不推倒现有题库模块，不混淆正式用户、会员、萌币和成长经验四类状态。

## 3. 用户状态与权益边界

### 3.1 四类状态必须独立

| 状态 | 含义 | 是否可消费 | P0 权益 |
|---|---|---|---|
| 非正式用户 | 已登录但未通过新人试炼的只读社区身份。 | 否 | 见 3.2。 |
| 正式用户 | 已通过新人试炼，获得正常社区参与资格。 | 否 | 现有社区参与能力。 |
| 会员 / 体验会员 | 限时会员权益；体验会员为一次性奖励。 | 否 | 对应会员档位权益与独立模型体验配额。 |
| 成长经验 / 等级 | 长期成长展示数据。 | 否 | P0 仅展示，不解锁功能。 |
| 萌币 / 积分 | 现有可获得、可消费资产。 | 是 | 保持现有规则。 |

不得使用 `vipTier` 代表正式用户状态，也不得将成长经验与萌币余额混用。

### 3.2 非正式用户：严格只读社区身份

非正式用户仅允许：

- 浏览与搜索公开内容；
- 点赞、收藏、关注；
- 查看个人基础资料；
- 签到；
- 进入成长中心并完成新人试炼、会员体验挑战。

非正式用户禁止：

- 创建、编辑、提交审核、发布或删除帖子；
- 发表评论、楼中楼回复、视频弹幕、漂流瓶及漂流瓶评论；
- 发送私信、群聊消息、语音信令，或创建、加入、邀请、管理群聊；
- 发起游戏匹配、进入可交互游戏房间或发送游戏房间聊天；
- 发起其他会产生公开内容、社交消息、房间状态或奖励状态的主动写操作。

正式用户通过新人试炼后恢复上述正常社区参与资格。管理员不受此限制。

前端必须隐藏或禁用入口并给出“完成新人试炼后可使用”的提示；后端必须在每个写入 Service 的入口再次校验，不能信任前端。

### 3.3 体验会员

会员体验挑战通过后发放 `TRIAL_900`：

- 体验期固定为 7 天；
- 体验权益以现有 900 积分档会员为基准；
- 每个账号一生仅可领取一次；
- 有效付费会员不得参与或领取体验奖励，避免覆盖、降级或叠加已购权益；
- 到期自动失效，重考不得续期；
- 奖励必须通过会员业务 Service 发放，保留独立奖励流水与幂等键。

模型可用范围按 900 积分档会员权益展示，但用量必须读取独立的 `TRIAL_900` 体验配额配置，不能直接复制付费会员完整配额。各模型的具体次数和周期作为运营配置维护，不写死在前端或题目配置中。

## 4. 成长中心页面

### 4.1 页面结构

成长中心入口替代当前用户侧“考试题库”入口，页面包含：

1. **我的成长**：当前身份、会员状态、成长等级、经验条、下一等级所需经验。
2. **新人试炼**：展示正式用户资格状态、挑战说明、答题入口与通过结果。
3. **会员体验挑战**：展示体验资格、剩余体验天数或已领取状态、答题入口。
4. **成长记录**：展示经验获得记录与挑战奖励记录。

题库内部可继续使用“做题”“背诵”“错题”“重点题”等交互，但成长挑战必须由成长中心统一进入与结算。

### 4.2 成长经验

P0 仅展示等级、总经验和经验流水，不绑定额外权限。

P0 可获得经验的来源仅限：

- 通过新人试炼；
- 通过会员体验挑战；
- 每日签到。

不按点赞数、评论数、浏览时长或普通发帖直接赠送经验，避免刷量。经验变化必须写入可追溯流水；同一来源事件只能结算一次。

## 5. 成长挑战

### 5.1 挑战类型

| 类型 | 目的 | 通过奖励 |
|---|---|---|
| `FORMAL_USER` 新人试炼 | 社区规则、安全意识与基础功能教育。 | 正式用户身份 + 成长经验。 |
| `VIP_TRIAL_900` 会员体验挑战 | 提供一次会员功能体验。 | 7 天 `TRIAL_900` + 成长经验。 |
| `ACTIVITY` 限时活动挑战 | 后续扩展，不属于 P0。 | 后续按活动配置。 |

### 5.2 出题与作答规则

- 每个挑战关联一套现有题库；题库继续负责题目、答案、解析和用户作答进度。
- 挑战负责抽题数量、及格规则、尝试上限、冷却时间与奖励规则；这些规则由后台配置，不由前端传入。
- 新人试炼题目应围绕社区规则、隐私、安全、举报和基础功能，不以技术知识作为正式用户门槛。
- 会员体验题目可使用站内功能、社区文化和趣味内容；不得通过高价值题目或可刷取题目变相发放长期权益。
- 判卷、通过判定、身份变更、经验发放和会员奖励必须由后端在同一业务链路中完成；客户端只展示结果。

### 5.3 挑战状态

挑战尝试状态使用枚举：`NOT_STARTED`、`IN_PROGRESS`、`PASSED`、`FAILED`、`REWARDED`、`EXPIRED`。

- 新人试炼通过后永久保留正式用户身份，除非管理员按独立治理流程撤销；P0 不提供用户自行降级。
- 会员体验挑战奖励一经领取即不可再次领取；挑战失败后的重试受后台配置的次数与冷却时间限制。
- 已通过或已领取的状态必须以数据库事实数据为准，不能只依赖前端缓存。

## 6. 数据模型建议

现有 `exam_question_bank`、`exam_question`、`exam_question_user_progress` 保持题库引擎职责，不直接改造成身份或会员表。

P0 新增业务事实数据建议如下：

| 表 | 用途 | 关键约束 |
|---|---|---|
| `user_growth_profile` | 用户正式状态、总经验、等级和当前成长快照。 | 用户唯一；包含 `create_time`、`update_time`、`delete_state`。 |
| `growth_challenge` | 挑战定义及关联题库、规则、状态。 | 挑战类型使用枚举；题库关联必须有效。 |
| `growth_challenge_attempt` | 用户每次挑战的答题、判定与失败记录。 | 用户、挑战、尝试序号唯一；服务端保存分数和状态。 |
| `growth_experience_log` | 经验发放流水。 | 来源类型与来源业务 ID 唯一，防重复加经验。 |
| `growth_reward_record` | 正式用户资格、体验会员等奖励流水。 | 用户、挑战、奖励类型唯一，作为幂等依据。 |

会员体验仍由既有会员领域维护到期和权益状态。成长模块只记录奖励事实并调用会员领域的受控发放方法，不直接更新会员字段。

## 7. 接口方向

| 接口 | 用途 |
|---|---|
| `GET /growth/overview` | 查询身份、会员体验、等级、经验和可参与挑战。 |
| `GET /growth/challenges/{challengeCode}` | 查询挑战说明、当前尝试状态和题目入口信息。 |
| `POST /growth/challenges/{challengeCode}/start` | 开始一次受控挑战。 |
| `POST /growth/challenges/{challengeCode}/submit` | 提交挑战并由服务端判卷、结算身份与奖励。 |
| `GET /growth/records` | 查询经验和奖励流水。 |

路径为建议；所有请求体必须使用 DTO，响应使用 VO，用户身份只从认证上下文取得。

## 8. 后端权限接入点

非正式用户限制必须覆盖所有真实写入入口，至少包括：

- 帖子草稿创建、编辑、提交审核、发布；
- 一级评论、楼中楼、视频弹幕；
- 私信、群聊消息、群聊成员和语音操作；
- 漂流瓶及其评论；
- 游戏匹配、房间输入和房间聊天。

建议通过统一的“正式用户资格” Service 校验或守卫层接入各业务 Service 的写入前置条件。它只做资格判断，不承载各业务的事务、结算和持久化主流程。

## 9. 明确不做

- 不做知识地图、学习路径、用户自建题库市场；
- 不做成长等级的实质权限解锁；
- 不做通过点赞、评论、浏览时长兑换经验；
- 不做体验会员的重复领取、续期或与付费会员叠加；
- 不把模型体验配额写死到前端；
- 不修改已有付费会员的权益和到期规则；
- 不因成长中心重写现有题库的题目、进度、错题和重点题逻辑。

## 10. 验收标准

- 非正式用户只能使用 3.2 的允许能力；直接调用被禁止写接口时，后端稳定拒绝。
- 前端所有被限制入口均有一致提示并引导至成长中心。
- 新人试炼通过后，用户立刻获得正式用户资格并可正常发帖与参与社区。
- 会员体验挑战通过后，仅符合条件的用户获得一次 7 天 `TRIAL_900`；已购会员状态不被覆盖或降级。
- 模型权益正确读取体验配额，而不是完整付费会员配额。
- 同一挑战的身份、经验和会员奖励在重复提交、网络重试或并发请求下只结算一次。
- 成长等级仅展示，不改变既有会员、积分或权限逻辑。

## 11. 实施顺序

1. 先提交当前未提交的题库代码，保留现有题库引擎作为独立退路。
2. 建立正式用户状态、挑战定义、尝试、经验和奖励流水的数据库迁移与枚举。
3. 实现成长挑战 Service、会员体验受控发放与模型体验配额策略。
4. 在所有社区写入 Service 接入正式用户资格校验，并完成权限回归。
5. 实现成长中心页面与前端限制提示。
6. 进行资格状态、重复领奖、会员叠加、到期、模型配额和核心写入链路的端到端验证。

## 12. P1 简化成长体系（已实现）

### 12.1 经验来源

当前只开放三种简单、可追溯的经验来源：

| 来源 | 经验 | 结算限制 | 状态 |
|---|---:|---|---|
| 新人试炼 | +100 XP | 每个账号仅结算一次。 | 已完成 |
| 会员体验挑战 | +80 XP | 每个账号仅结算一次。 | 已完成 |
| 每日签到 | +5 XP | 每个账号每个自然日仅结算一次。 | 已完成 |
| `ACTIVITY` 活动挑战 | 按活动配置 | 仅保留来源类型，本期不开放。 | 预留 |

发帖、评论、点赞、收藏、浏览、最佳答案、连续签到和个人资料完善均不发放成长经验。当前不建设每日任务、每周任务、勋章、称号、权益解锁或经验回收流程。

### 12.2 等级路径

成长等级只用于展示，不参与正式用户、会员或其他业务权限判定。正式用户权限继续只读取 `formal_state`。

| 等级 | 名称 | 累计经验 | 展示说明 |
|---|---|---:|---|
| Lv.1 | 萌芽 | 0 XP | 初次进入社区。 |
| Lv.2 | 初识 | 100 XP | 通常已完成新人试炼。 |
| Lv.3 | 同行 | 250 XP | 稳定使用社区功能。 |
| Lv.4 | 成长 | 500 XP | 持续参与社区互动。 |
| Lv.5 | 共创 | 900 XP | 长期活跃并参与共创。 |
| Lv.6 | 守望 | 1500 XP | 陪伴社区成长的长期成员。 |

### 12.3 页面与接口

- 总览经验条按当前等级区间计算，不再使用每 100 XP 升一级的线性规则。
- 成长里程固定展示 Lv.1～Lv.6，等级说明弹窗展示名称、门槛和说明，不绑定权益。
- 成长记录默认展示最新 5 条，用户点击“查看全部”后使用后端分页继续浏览。
- `GET /growth/records?pageNum=1&pageSize=5` 返回当前登录用户的经验流水，用户身份只从认证上下文获取。
- 经验结算统一通过成长经验 Service 完成，依靠用户、来源类型和来源业务 ID 唯一约束保证幂等。

### 12.4 P1 验收标准

- 挑战与签到均通过统一服务写入经验流水并更新成长快照。
- 同一签到或挑战事件重复请求不会重复增加经验。
- 等级在 0、100、250、500、900、1500 XP 边界正确变化。
- 成长记录具备加载中、错误、无权限、空数据和分页状态，并适配深色模式。
- 成长等级变化不会改变正式用户、会员和萌币权益。
