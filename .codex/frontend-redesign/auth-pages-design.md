# 萌部落认证页统一重设计方案

日期：2026-07-16

## 1. 目标

将登录、注册、找回密码三页统一为“社区门厅”设计语言：保留萌部落的二次元角色与温暖氛围，降低海报感和组件堆叠感，让用户首先看清当前任务、表单字段和唯一主操作。

本次只调整前端布局、样式、响应式与交互呈现，不新增数据库表、字段、后端接口、权限逻辑或业务流程。

## 2. 已确认的视觉方向

- 使用 A「社区门厅」布局与 A1「纯场景插画」方案。
- 登录、注册、找回密码使用同一角色、同一空间、同一粉蓝暖白色系的三张系列图。
- 插画内不放站名、宣传文字、按钮、功能卡或其他 UI；品牌文字由 HTML 渲染。
- 桌面端以插画作为认证卡片的连续背景画布，表单位于图片右侧自然留白区域，不再使用生硬分割线。
- 移动端保留约三分之一屏的场景图，表单以白色纸张式面板上浮承接，不再直接隐藏全部插画。
- 视觉使用暖白、粉蓝和低饱和珊瑚红；不使用紫蓝 AI 渐变、堆叠玻璃拟态和过重阴影。

## 3. 页面布局

### 3.1 登录页

- 右侧首先显示小型英文眉题、`欢迎回来` 主标题和一句任务说明。
- 登录方式保持一层导航：`验证码`、`账号密码`、`邮箱`。
- 邮箱登录进入表单后，以轻量文字入口切换密码或验证码方式，不再显示第二层大卡片选择器。
- 表单标签位于输入框上方；手机号国家码、验证码发送按钮保留在输入框内部的组合区域。
- `登录` 是唯一实色主按钮。
- `创建账号` 使用强调文字，`先逛逛` 使用普通文字链接，不再与主按钮形成三按钮竞争。
- 用户协议与隐私政策位于主按钮前；未勾选时在该区域就地提示。
- 用户名或邮箱密码模式在密码标签右侧显示 `忘记密码`。
- 备案号、帮助入口置于表单底部弱化展示。

### 3.2 注册页

- 使用 `加入萌部落` 主标题和简短说明，继续沿用同一认证壳层。
- 不改变当前单页注册业务流程。
- 宽屏下用户名与显示昵称并排，手机与邮箱并排；密码独占一行。
- 中小屏及移动端全部改为单列，取消固定 `400px` 最小宽度，消除横向滚动条。
- 必填项与选填项使用清晰文字标识，不仅依赖红色星号。
- `立即创建账号` 是唯一主按钮，`已有账号，直接登录` 为文字入口。
- 协议区紧邻主按钮，并保留现有行为验证码触发顺序。

### 3.3 找回密码页

- 使用 `找回密码` 主标题和安心、直接的任务说明。
- 邮箱与手机找回继续使用同一层分段切换，不新增步骤或后端状态。
- 表单按 `账号 → 验证码 → 新密码` 的顺序纵向排列。
- 获取验证码保持输入框内组合操作；倒计时、发送中和禁用态保持现有逻辑。
- `重置密码并登录` 是唯一主按钮，`返回登录` 为文字入口或弱按钮。
- 提交失败时在对应字段或表单顶部显示明确错误，不改变后端返回语义。

## 4. 共同组件与职责

实施时优先复用当前技术栈，不引入新依赖。

- `AuthSceneShell`：负责桌面/移动认证壳层、场景图、品牌锁定区、表单承载区和底部备案区。
- 页面视图：只组合各自表单与页面文案，不承载共享布局细节。
- 现有 `SignIn.js`、`SignUp.js`、`ForgotPassword.js`：继续负责表单状态、校验、验证码、人机验证和 API 调用；本次不改变后端契约。
- 现有 `SiteIcpLink` 与 `BehaviorCaptchaDialog`：继续复用。

为了控制首次改动风险，先在登录页验证共同壳层的 DOM 与样式边界；确认构建和桌面/移动表现后，再抽取共享组件并迁移另外两页。

## 5. 交互与状态

- 所有异步提交保留加载态，并在加载时禁用重复提交。
- 验证码发送保留发送中、倒计时和禁用态。
- 字段错误优先在字段附近展示；全局消息只承担无法归属到单个字段的错误。
- 键盘焦点必须有清晰可见的描边，不能只依赖阴影或颜色变化。
- 页签使用正确的激活状态和键盘可访问语义。
- 按钮按下使用轻微位移或缩放反馈，动画使用 `transform` 与 `opacity`，时长控制在 180–260ms。
- 尊重 `prefers-reduced-motion`，减少进入动画与位移动画。

## 6. 响应式规则

- 桌面宽度大于 900px：完整场景画布与右侧表单共存。
- 900px 及以下：切换为顶部场景图和上浮表单面板。
- 移动端不设置大于视口的固定宽度；认证根容器使用 `min-height: 100dvh`，允许页面自然滚动。
- 键盘弹出、短屏和横屏下，所有字段、协议与提交按钮必须可滚动到达。
- 输入框与主按钮的可点击高度不低于 44px。

## 7. 不在本次范围

- 不修改登录、注册、找回密码 API。
- 不合并手机号、用户名、邮箱的后端认证模型。
- 不新增第三方登录、扫码登录或社交账号绑定。
- 不修改行为验证码规则。
- 不新增深色认证主题；认证页继续使用当前浅色主题。
- 不重设计用户协议、隐私政策和备案详情页。

## 8. 验收标准

- 登录页不再出现邮箱页签中的第二层大卡片选择。
- 三页桌面端具有一致的标题、字段、主按钮和次级入口层级。
- 三页移动端保留品牌场景，同时无横向滚动条。
- 390×844、768×1024、1440×900 三种视口下内容完整可达。
- 原有手机号验证码、用户名密码、邮箱密码、邮箱验证码、注册、邮箱找回和手机找回流程保持可用。
- 协议、验证码、人机验证、加载态与错误态保持可用。
- 前端运行 `npm run build` 通过，且新增或修改代码中没有 `console.log`。

## 9. 风险与控制

- 认证页当前样式同时受全局 Element Plus 覆盖和页面 scoped CSS 影响；实施时使用认证页明确命名的类，避免扩大全局覆盖。
- 新插画文件体积较大；进入正式代码前需转换并压缩为 WebP，避免直接打包原始 PNG。
- 现有 Live2D 可能在认证路由切换瞬间残留全局 DOM；该问题与本次布局重设计分开验证，不在未确认前顺手改动。
- 首轮只实现登录页并完成构建和浏览器回归，再迁移注册与找回密码，降低三页同时变化的回归范围。
