# 萌部落认证页统一重设计方案

日期：2026-07-16

## 1. 目标

登录、注册、找回密码三个认证页恢复萌部落原有的粒子海洋背景和淡红小红书风格。三页使用完全一致的单层分栏卡片：左侧三分之二展示插画，右侧三分之一承载表单，不再使用整图背景叠加表单小卡片。

本次只调整正常桌面端前端布局、样式与登录方式呈现，不新增数据库表、字段、接口、权限逻辑或业务流程，不专项适配移动端。

## 2. 统一认证壳层

- `App.vue` 现有 `ParticleSea` 继续只在 `layout: auth` 的三个认证路由显示。
- `.auth-page` 保持透明，让粒子海洋完整可见；认证页不得增加覆盖全屏的不透明背景。
- 三页共用同一 `.auth-card` 尺寸，不再使用注册页加高卡片。
- 卡片使用单层 CSS Grid，列宽严格为 `2fr 1fr`。
- 左侧图片和右侧表单均是卡片内部的普通网格列，不使用绝对定位叠层，不增加第二张表单卡片。
- 桌面卡片宽度上限为 `1200px`，高度上限为 `700px`；在 1280×720 视口内按可用空间收缩。
- 卡片外层保持轻量圆角与淡红阴影，内部不使用过重阴影或棕色主题。

## 3. 视觉主题

- 主色恢复项目既有 `--primary-red: #ff2442`，悬停色使用 `--primary-hover: #e61f3c`。
- 浅色底使用 `#ffffff`、`#fffafb`、`#f7f8fa` 和 `--primary-pale: #fff0f1`。
- 页签激活线、主按钮、文本链接、输入框聚焦态统一使用淡红体系。
- 输入框保持扁平圆角，不使用棕色按钮、暖棕标题或米黄色大面积背景。
- 备案号使用 11px 左右浅灰文字，取消粗体和显眼分隔线，固定在右侧内容区底部弱化展示。

## 4. 左侧图片区

- 三页继续使用现有三张本地 WebP，方便后续由用户直接替换图片文件。
- 图片使用 `object-fit: cover`，不在图片内写死文字。
- 左下角仅放一个轻量淡灰亚克力文字块，使用半透明灰白背景、细边框和模糊，不对整张图片增加大面积遮罩。
- 删除所有英文眉题。
- 标题加粗，并使用短红色装饰线增强识别；不得使用大段海报文案。
- 登录页：标题 `遇见同好`，描述 `一个交友、发帖与娱乐兼具的社区。`
- 注册页：标题 `加入萌部落`，描述 `认识新朋友，也分享你的兴趣与日常。`
- 找回密码页：标题 `重新出发`，描述 `验证账号后，很快就能回到社区。`

## 5. 登录页

- 右侧顶部只显示居中、大号、加粗的品牌名 `萌部落`。
- 删除 `欢迎回来`、任务说明和英文眉题。
- 登录方式改为四个同级页签：`短信验证码`、`账号密码`、`邮箱验证码`、`邮箱密码`。
- 不再出现邮箱页签内的密码/验证码二级切换器。
- 四个入口继续映射现有接口：
  - 短信验证码 → `smsLogin`
  - 账号密码 → `login`
  - 邮箱验证码 → `mailLogin`
  - 邮箱密码 → `login`
- 账号密码和邮箱密码模式的 `忘记密码` 都作为弱按钮，与密码输入框位于同一行右侧。
- 用户协议与隐私政策必须位于登录主按钮上方。
- `登录` 是唯一实色主按钮。
- 主按钮下方整理为两个弱入口：`创建账号` 和 `先逛逛`，使用文字层级和细分隔线，不使用第二、第三个实色按钮。

## 6. 注册页

- 使用同一张 2:1 分栏卡片和相同右侧宽度。
- 右侧顶部显示居中的品牌名 `萌部落`，下方仅保留简洁名词标题 `创建账号`。
- 保持当前单页注册字段、校验、协议和行为验证码顺序不变。
- 用户名与显示昵称并排，手机与邮箱并排，密码独占一行。
- 协议位于主按钮上方，`创建账号` 是唯一实色主按钮，`返回登录` 是文字入口。

## 7. 找回密码页

- 使用同一张 2:1 分栏卡片和相同右侧宽度。
- 右侧顶部显示居中的品牌名 `萌部落`，下方仅保留简洁名词标题 `找回密码`。
- 邮箱与手机保持同一层分段切换，不新增步骤。
- 表单顺序保持 `账号 → 验证码 → 新密码`。
- `重置密码` 是唯一实色主按钮，`返回登录` 是文字入口。

## 8. 组件与数据边界

- `auth-split-layout.css`：只负责三页共享卡片尺寸、2:1 网格、图片区、亚克力文案和右侧内容区。
- `signin.css`、`signup.css`、`forgot.css`：分别负责各自表单布局和状态样式。
- `SignIn.js`：登录页签调整为四种枚举，但 API、验证码、人机验证、加载态和跳转语义不变。
- `SignUp.js`、`ForgotPassword.js`：业务逻辑不变。
- 不新增共享 Vue 组件，不引入新依赖。

## 9. 验收标准

- 三个认证页都能看到原有粒子海洋背景。
- 同一桌面视口下三页卡片的宽度、高度和左右列比例一致。
- 页面只有一张认证卡片，内部为左图右表单，不存在浮在图片上的表单小卡片。
- 三页恢复 `#ff2442` 淡红小红书主题，不再出现棕色主按钮和棕色激活态。
- 登录页恰好有四个一级登录方式，邮箱不再出现二级切换器。
- 两个密码登录方式的忘记密码按钮都与密码框同行且位于右侧。
- 登录与注册协议均位于主按钮上方。
- 左侧无英文眉题，只有短标题和一行描述。
- 备案号被弱化，不抢占主视觉。
- 1280×720、1440×900、1920×1080 无横向滚动，表单操作完整可达。
- `node --test tests/auth-desktop-layout.test.mjs` 和 `npm run build` 通过，修改代码中不存在 `console.log`。

## 10. 风险控制

- 共享布局只作用于认证页 CSS，不修改全站粒子组件和全局主题变量。
- 登录页只重排既有四种认证路径，不修改请求参数、接口和认证上下文。
- 用户后续替换图片时只需覆盖三个 WebP 文件，不需要改模板或 CSS。
- 现有 Live2D 外部请求与认证页无关，不在本次顺手修改。
