# 首页信息架构与“为你推荐”P0 PRD

## 0. P0 实施状态（2026-07-12）

以下确认需求已完成并提交实现：

- [x] 左侧内容发现收敛为“首页、为你推荐”；热帖榜改为首页右侧悬浮的行式榜单，不再占用左侧入口，支持后端分页（每页 10 条、最多 50 条）及收起/展开；前端不预取全榜或自行切页。
- [x] 首页顶部一级分类支持悬停与点击展开细分板块；下拉面板只展示细分板块，菜单具备下移缓冲，鼠标从触发器移入面板不会闪退。
- [x] 首页全站流以新帖为主，并随机混入少量高互动公开帖；热帖榜算法本身不改动。
- [x] 已接入规则推荐接口、兴趣保存、帖子级“不想看”、推荐理由、游客公共兜底和个性化关闭逻辑。
- [x] 登录用户尚未选择兴趣时，推荐页使用公共帖子作为模糊背景，并以居中“选择兴趣”入口拦截阅读。
- [x] 兴趣弹窗标题为“兴趣卡片”，仅保留板块勾选和“保存”；保存时默认开启个性化推荐。
- [x] 个性化推荐开关迁入“账号与安全”，位于“登录日志”下方。

## 1. 结论

首页不再把“全站浏览”和“个性化推荐”混成一个入口。

- 左侧内容入口收敛为：`首页`、`为你推荐`。
- `热帖榜`保留原有热度算法，改为仅在首页右侧展示的悬浮行式榜单。
- 原左侧所有分类移入“首页”内容区顶部，采用“一级分类 + 悬停展开细分板块”的二级导航。
- 原左侧的“推荐”改名为“为你推荐”，由全站帖子列表升级为规则推荐流。
- “为你推荐”每屏少量混入已关注作者的近期帖子，但不能退化成关注流。

目标是减少左侧拥挤，让用户在首页发现板块内容，在推荐页看到适合自己的内容；两者均保留热帖作为稳定兜底。

## 2. 当前现状与改造原因

当前左侧菜单同时展示“推荐”“热帖榜”和所有一级分类。点击“推荐”时，前端仍按 `boardId = 0` 调用现有全站帖子分页接口，因此它本质上是全站帖流，并非个性化推荐。分类页面则先选中一级分类，再默认进入该分类下的第一个细分板块。

仓库已经具备分类、细分板块、帖子标签、点赞、收藏、评论、关注关系和热帖榜等基础信号；首页卡片也已有“来自已关注作者”的展示能力。因此 P0 不需要引入 AI 或重新建设内容体系。

## 3. P0 范围

### 3.1 左侧导航

左侧“内容发现”区域按以下顺序展示：

1. `首页`：全站公开内容的浏览入口，默认展示最新公开帖子。
2. `为你推荐`：登录用户的个性化推荐流；游客展示公共兜底流。
3. `热帖榜`：保留现有 Redis 热榜逻辑，改为首页右侧悬浮的行式榜单，不再作为左侧菜单或独立内容流入口。

原先在左侧逐条展示的一级分类全部移除。游戏中心、漂流瓶、题库、积分商城等“快速入口”保持原位置和行为，不属于本次改造。

### 3.2 首页内容区的板块导航

用户点击左侧“首页”后，右侧内容区在顶栏下、帖子流上方展示一条紧凑的板块导航：

- 默认项为“全部”，展示全站最新公开帖子。
- 每个一级分类作为一个导航项。
- 桌面端鼠标悬停一级分类，展示该分类下的细分板块菜单；触发器与菜单之间必须存在命中桥接或关闭延迟，鼠标下移至菜单时不得闪退；点击细分板块后，帖子流切换为该板块的公开帖子。
- 触屏端不依赖悬停，点击一级分类展开同一份细分板块菜单，再点击具体板块。
- 选中细分板块后，导航应清楚显示“一级分类 / 细分板块”的当前状态；用户可点击“全部”返回首页全站流。

本期不增加新的“分类详情页”或新的路由页面。首页状态可通过现有首页状态及查询参数恢复，例如当前页面类型、分类和板块 ID；具体参数名在实施时统一确定。

### 3.3 “为你推荐”流

`为你推荐`与首页全站流是两个独立结果集：

- 首次登录用户可选择 3～8 个感兴趣的细分板块；未选择兴趣时，不直接阅读推荐内容，而是以公共帖子毛玻璃背景展示居中的“选择兴趣”入口。
- 已选择兴趣的用户可从推荐页进入兴趣管理；个性化推荐开关位于“账号与安全”的“登录日志”下方。
- 推荐卡片展示一条真实、可解释的原因，例如“因为你选择了游戏交流”“因为你收藏过同板块内容”“来自你关注的作者”。
- 卡片菜单提供“不想看这篇”；操作后该帖子不再进入该用户的推荐流。
- 设置页提供“管理兴趣”“清空兴趣与推荐反馈”“关闭个性化推荐”。关闭后推荐页退回公共兜底流。

### 3.4 已关注作者帖的混入规则

关注关系是推荐流的增强信号，不单独创建“关注”页：

- 每 20 条推荐最多放入 2～4 条已关注作者的近期公开帖子。
- 单个作者在一屏最多 1 条，避免关注人数较多时压制兴趣探索。
- 已关注作者帖子仍必须通过已发布、未删除、当前用户可见等过滤。
- 用户没有关注任何人、候选不足或查询失败时，按其他候选补齐。

这样能让用户感知到关注关系的价值，同时维持“为你推荐”的发现属性。

## 4. 推荐规则

### 4.1 候选过滤

排序前必须由 Java 服务过滤：

- 仅已发布、未逻辑删除、公开可见的帖子；
- 不推荐用户自己发布的帖子；
- 排除用户选择“不想看”的帖子；
- 执行现有的用户可见性、内容状态和权限判断。

缓存和推荐算法都不是权限来源；帖子状态变化后，最终返回前仍需回查或确保失效。

### 4.2 P0 混排

一页默认 20 条，优先按以下构成混排：

| 来源 | 目标数量 | 说明 |
|---|---:|---|
| 显式兴趣与已有互动所在板块 | 约 10～12 条 | 主体内容，优先匹配用户选择的细分板块；点赞、收藏、评论可作为补充信号。 |
| 已关注作者近期帖子 | 2～4 条 | 见 3.4 的上限。 |
| 新发布公开帖子 | 约 3～4 条 | 为新创作者保留曝光，避免推荐流只剩旧内容。 |
| 热帖榜候选 | 约 2～4 条 | 内容不足或冷启动时优先补齐。 |

同一作者、同一细分板块在一页中的连续出现需要受限。具体分值允许后台配置或常量管理，但 P0 不引入模型训练、向量召回或 AI 重排序。

### 4.3 冷启动与降级

| 情况 | 返回策略 |
|---|---|
| 游客 | 不建立画像，展示最新公开帖与热帖混排。 |
| 登录用户未选择兴趣 | 返回公共帖子作为模糊背景，页面以“选择兴趣”入口拦截阅读。 |
| 用户已选兴趣但相关帖子不足 | 兴趣内容优先，其余由新帖和热帖补齐。 |
| 推荐计算、缓存或依赖异常 | 直接降级为公共兜底流；不得影响首页、点赞、收藏、评论或关注。 |
| 用户关闭个性化推荐 | 不读取其兴趣和互动信号，展示公共兜底流。 |

## 5. 数据与接口建议

本期仅新增必要的用户状态；现有点赞、收藏、评论、关注记录继续作为推荐信号，不新增浏览时长或完整行为事件大表。

### 5.1 建议新增数据

| 表 | 用途 | 关键约束 |
|---|---|---|
| `user_interest_preference` | 保存用户手选的细分板块兴趣和个性化开关。 | 用户与板块唯一；使用 BIGINT 自增主键，包含 `create_time`、`update_time`、`delete_state`。 |
| `user_recommend_feedback` | 保存“不想看这篇”的帖子级反馈。 | 用户与帖子唯一；后续若扩展作者/板块负反馈，应使用业务枚举，不在 P0 预建无用字段。 |

推荐缓存和已展示去重可以使用 Redis，例如 `recommend:feed:{userId}:{page}:{profileVersion}` 与短期已展示集合。Redis 丢失只允许导致少量重复，不得造成权限泄露或改变原始业务数据。

### 5.2 建议接口

| 接口 | 用途 |
|---|---|
| `GET /recommend/feed` | 获取为你推荐分页；用户身份只从认证上下文读取。 |
| `GET /profile/interests` | 查询我的兴趣设置与个性化开关。 |
| `PUT /profile/interests` | 整体保存已选细分板块与开关。 |
| `POST /recommend/feedback/not-interested` | 仅接收帖子 ID；后端自行校验帖子和当前用户。 |
| `POST /profile/interests/reset` | 清空兴趣与推荐反馈，并使推荐缓存失效。 |

接口路径为建议，实施时必须遵循现有 `Controller → Service → Mapper` 分层、DTO/VO 和认证上下文规范。

## 6. 交互细节

1. 登录用户首次打开“为你推荐”且无兴趣时，以公共帖子毛玻璃背景展示居中的“选择兴趣”入口。
2. 兴趣弹窗标题固定为“兴趣卡片”，按“一级分类分组 + 细分板块可选”展示；仅保留关闭、板块勾选与“保存”。
3. 保存兴趣时默认开启个性化推荐；开关仅在“账号与安全”的“登录日志”下方展示。
4. 首页板块导航的悬停菜单离开后关闭；从一级分类移动至菜单时不得闪退。
4. 在“为你推荐”点击帖子、返回列表、翻页时保留当前流类型和滚动位置。
5. 推荐理由只展示实际命中的单一主要原因；没有可靠理由时显示“社区正在讨论”，不伪造个性化解释。
6. 不想看操作需要立即从当前列表移除，并在下次请求中保持生效；提交期间禁用重复点击。

## 7. 明确不做

- 不新增关注流、好友动态流或群聊动态流；
- 不接入 AI、RAG、Embedding、LLM 或向量重排序；
- 不采集私信、群聊内容、完整搜索词或敏感兴趣；
- 不做“少看此类”“屏蔽作者”、复杂负反馈权重和推荐实验平台；
- 不改造热帖榜算法；
- 不把分类导航再复制回左侧。

## 8. 验收标准

- 左侧只出现首页、为你推荐两项内容发现入口，分类不再挤占左侧高度；热帖榜固定在首页右侧以行式榜单展示。
- 首页可从顶部分类导航稳定进入任一细分板块，并可回到“全部”全站流。
- 已选兴趣的用户在为你推荐中优先看到对应细分板块内容；每 20 条最多出现 4 条已关注作者帖子。
- 推荐理由、隐藏帖子、兴趣修改、清空与关闭个性化推荐均可立即生效。
- 游客、无兴趣用户和推荐服务异常用户仍能浏览公开内容。
- 删除、下线或不可见帖子不会出现在推荐结果中。
- 首页、为你推荐、热帖榜三种流的加载中、错误、无权限和空数据状态均被处理。

## 9. 实施顺序

1. 先完成现有题库工作并单独提交，避免与首页改造混在同一提交中。
2. 完成首页信息架构与顶部分类导航，保持全站流、热帖榜原逻辑可用。
3. 增加兴趣设置、帖子级“不想看”和规则推荐接口。
4. 前端接入为你推荐、兴趣引导、推荐理由和设置入口。
5. 进行权限回归、空数据/降级验证和前端构建验证。
