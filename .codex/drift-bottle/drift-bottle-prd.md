## 1. 背景

论坛计划新增漂流瓶模块，作为一个轻量树洞。用户可以匿名丢出一段心事，其他用户随机捞到后可以查看和评论，但双方都不知道真实身份。

漂流瓶不是帖子广场，也不是私信系统。它的核心是匿名表达、随机相遇、温和回应，同时后台必须保留治理能力。

本需求只定义漂流瓶第一阶段能力，不实现代码。

## 2. 产品定位

漂流瓶定位：

- 匿名树洞。
- 随机打捞。
- 弱关系互动。
- 温和评论。
- 后台可治理。

与现有模块区别：

| 模块 | 核心关系 | 是否显示作者 | 互动方式 |
|---|---|---|---|
| 帖子 | 公开表达 | 显示作者 | 评论、点赞、收藏、搜索 |
| 私信 | 明确对象 | 双方可见 | 一对一会话 |
| 漂流瓶 | 随机相遇 | 匿名展示 | 捞瓶、评论、举报 |

P0 不把漂流瓶做成另一个帖子列表，也不做公开热榜。

## 3. P0 目标

- 用户可以扔一个文字瓶子。
- 用户可以随机捞到一个可见瓶子。
- 用户可以查看瓶子详情和评论。
- 用户可以匿名评论瓶子。
- 用户可以查看自己扔过的瓶子。
- 用户可以删除自己的瓶子。
- 用户可以举报瓶子或评论。
- 前端不展示瓶子作者真实信息。
- 后端保留真实 `userId` 供删除、举报、风控、封禁使用。

## 4. P0 非目标

- 不做点赞。
- 不做收藏。
- 不做热门榜。
- 不做关注作者。
- 不做作者主页跳转。
- 不做私聊瓶主。
- 不做图片瓶子。
- 不做语音瓶子。
- 不做外链。
- 不做楼中楼评论。
- 不做 WebSocket 实时评论。
- 不把漂流瓶纳入普通帖子搜索和推荐。

## 5. 匿名规则

### 5.1 瓶子作者展示

- 数据库保存真实作者 `userId`。
- 面向普通用户的 VO 不返回真实作者 ID、昵称、头像。
- 瓶子作者统一展示为 `瓶主`。
- 用户查看自己扔出的瓶子时，可以标记 `isOwner = true`，但仍不展示公开作者资料。

### 5.2 评论者展示

- 数据库保存真实评论者 `userId`。
- 面向普通用户的 VO 不返回真实评论者 ID、昵称、头像。
- 评论者展示为 `路过的人 A`、`路过的人 B`、`路过的人 C`。
- 同一个用户在同一个瓶子下的匿名身份必须稳定。
- 不同瓶子之间匿名身份不串联，避免跨瓶追踪。

示例：

```text
用户 100 在瓶子 1 下显示为：路过的人 A
用户 100 在瓶子 2 下可以显示为：路过的人 C
```

### 5.3 后台治理

匿名只对普通用户生效。

后端和后台治理能力必须可以追溯：

- 瓶子真实作者。
- 评论真实作者。
- 举报人。
- 删除操作人。
- 创建时间和 IP 风控信息，具体是否落库由后续实现评估。

## 6. 核心玩法

### 6.1 扔瓶子

用户填写：

- 内容。
- 心情标签。

建议心情标签：

```text
开心
难过
迷茫
压力
秘密
求安慰
随便说说
```

P0 内容限制：

- 瓶子内容 20 - 500 字。
- 必须登录。
- 被禁言用户不能扔瓶子。
- 每人每天最多 5 个瓶子。

### 6.2 捞瓶子

用户点击“捞一个瓶子”，系统随机返回 1 个可见瓶子。

规则：

- 优先返回用户近期未捞过的瓶子。
- 不返回用户自己扔的瓶子。
- 不返回已删除、隐藏、审核未通过的瓶子。
- 短时间内尽量不重复返回同一瓶子。
- 每人每天最多捞 20 次。

用户捞到后可以：

- 放回海里。
- 写一句回应。
- 举报。

### 6.3 评论瓶子

评论规则：

- 评论内容 1 - 200 字。
- 必须登录。
- 被禁言用户不能评论。
- 评论匿名展示。
- P0 只做一级评论，不做楼中楼。
- 同一用户不能在同一瓶子下连续刷屏。

### 6.4 我的瓶子

用户可以查看：

- 自己扔出的瓶子。
- 每个瓶子的评论数。
- 每个瓶子最近评论。
- 瓶子状态。

用户可以删除自己的瓶子。

## 7. 状态设计

### 7.1 瓶子状态

```text
VISIBLE
HIDDEN
DELETED
```

说明：

- `VISIBLE`：正常可被捞到。
- `HIDDEN`：因举报、风控或后台处理暂时隐藏。
- `DELETED`：作者删除或后台删除。

### 7.2 评论状态

```text
VISIBLE
HIDDEN
DELETED
```

说明：

- `VISIBLE`：正常展示。
- `HIDDEN`：因举报、风控或后台处理暂时隐藏。
- `DELETED`：作者删除或后台删除。

## 8. 数据模型建议

P0 建议独立建表，不复用 `article` 和 `message`。

原因：

- 漂流瓶需要匿名展示。
- 漂流瓶不需要普通帖子热度、收藏、搜索、主页等能力。
- 强行复用帖子会导致作者隐藏、推荐排除、搜索排除、评论身份重算等逻辑到处打补丁。

### 8.1 drift_bottle

| 字段 | 说明 |
|---|---|
| `id` | 主键 |
| `user_id` | 真实作者用户 ID |
| `content` | 瓶子内容 |

| `status` | VISIBLE / HIDDEN / DELETED |
| `comment_count` | 评论数 |
| `picked_count` | 被捞次数 |
| `create_time` | 创建时间 |

## 9. 接口建议

| 接口 | 方法 | 说明 |
|---|---|---|
| `/drift-bottle/create` | POST | 扔瓶子 |
| `/drift-bottle/pick` | GET | 随机捞一个瓶子 |
| `/drift-bottle/{id}` | GET | 查看瓶子详情 |
| `/drift-bottle/{id}/comment` | POST | 评论瓶子 |
| `/drift-bottle/mine` | GET | 我的瓶子 |
| `/drift-bottle/{id}` | DELETE | 删除自己的瓶子 |
| `/drift-bottle/{id}/report` | POST | 举报瓶子 |
| `/drift-bottle/comments/{commentId}/report` | POST | 举报评论 |

约束：

- 所有写操作从登录态获取用户 ID。
- 禁止信任前端传入的用户 ID 或角色。
- 请求体使用独立 DTO。
- 响应使用 VO。
- 不直接返回 Entity。

## 10. 风控与治理

### 10.1 发布限制

- 被禁言用户不能扔瓶子、不能评论。
- 每人每天最多扔 5 个瓶子。
- 每人每天最多评论 50 条。
- 每人每天最多捞 20 次。
- 同一用户不能在同一瓶子下连续刷屏。

### 10.2 内容限制

- P0 只允许纯文本。
- 不允许图片。
- 不允许语音。
- 不允许外链。
- 文本需要复用现有内容校验能力。

### 10.3 举报处理

- 用户可以举报瓶子。
- 用户可以举报评论。
- 同一用户不能重复举报同一目标。
- 被举报达到阈值的瓶子或评论可以先自动隐藏。
- 后续后台再处理举报结果。

### 10.4 Guard Chain 边界

漂流瓶可以使用局部 Guard Chain 做前置准入校验，例如：

- 用户是否可发言。
- 内容长度是否合法。
- 今日发布次数是否超限。
- 评论目标是否存在且可见。
- 是否重复举报。

Guard Chain 只回答“能不能继续”，真正的落库、计数、状态流转、举报处理仍由 Service 主流程负责。

## 12. 阶段规划

### P0：文字树洞

- 扔瓶子。
- 随机捞瓶子。
- 匿名评论。
- 我的瓶子。
- 删除自己的瓶子。
- 举报瓶子和评论。
- 基础风控限制。

### P1：体验增强

- 心情筛选。
- 只看未回应瓶子。
- 瓶子收到评论后的站内通知。
- 最近捞过记录。
- 轻量统计，例如被捞次数、回应次数。

### P2：治理与分发增强

- AI 安全辅助审核。
- 长期无人回应瓶子再分发。
- 树洞精选。
- 后台举报处理页。
- 定时沉底或过期隐藏。

## 13. 验收标准

- 用户可以成功扔出文字瓶子。
- 用户可以随机捞到非自己的可见瓶子。
- 用户短时间内不会反复捞到同一个瓶子。
- 用户可以匿名评论瓶子。
- 瓶主和评论者真实身份不会出现在普通用户响应中。
- 同一用户在同一瓶子下匿名身份稳定。
- 不同瓶子之间匿名身份不串联。
- 用户可以查看和删除自己的瓶子。
- 被禁言用户不能扔瓶子或评论。
- 发布、评论、捞瓶次数限制生效。
- 用户可以举报瓶子和评论。
- 被举报达到阈值的内容可以隐藏。
- 漂流瓶不进入普通帖子搜索、推荐和作者主页。
