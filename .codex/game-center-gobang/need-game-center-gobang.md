# 萌部落论坛游戏中心与五子棋需求文档

> 文档版本：V0.1
>
> 编写日期：2026-06-18
>
> 本文档记录论坛系统“游戏中心模式”第一期需求，第一款游戏为五子棋。
>
> 参考实现：`C:\JavaCode\java-ee-career\gobang-demo`

## 1. 总体定位

- 游戏中心是论坛用户端的轻量实时娱乐模块，入口放在用户端前台，不进入管理端第一期范围。
- 第一款游戏为 **五子棋**，以在线匹配、双人对战、胜负结算、积分战绩为核心闭环。
- 游戏中心沿用论坛现有登录、JWT、用户资料、头像、积分体系的基础能力，但游戏对局积分与论坛积分隔离，避免影响签到、商城、抽奖等既有业务。
- WebSocket 采用三层连接模型：
  - 游戏大厅连接：展示游戏中心在线状态、游戏卡片、全局公告、用户游戏状态。
  - 单个游戏连接：进入五子棋后连接，用于匹配队列、游戏内大厅、排行榜刷新。
  - 单个房间连接：匹配成功后连接具体房间，用于准备、落子、认输、断线、结算。
- 现有 `/ws/notify` 只服务私信、审核、系统消息，不承载游戏实时消息。

## 2. 一期建设范围

### 2.1 游戏中心大厅

- 登录用户可进入游戏中心页面。
- 展示至少一个游戏卡片：五子棋。
- 展示当前用户的游戏摘要：
  - 总对局数。
  - 胜局数。
  - 负局数。
  - 胜率。
  - 五子棋天梯积分。
- 大厅 WebSocket 连接成功后，服务端可推送：
  - 游戏中心在线人数。
  - 用户当前游戏状态：空闲、匹配中、对局中。
  - 五子棋游戏可用状态。
- 未登录用户访问游戏中心时，按论坛现有登录提示处理。

### 2.2 五子棋游戏页

- 用户点击五子棋后进入五子棋游戏页，并建立五子棋游戏级 WebSocket。
- 游戏页展示用户五子棋资料、积分、胜率、匹配入口。
- 支持开始匹配、取消匹配。
- 匹配成功后进入房间页，关闭或降级游戏级匹配状态。
- 同一用户同一时间只能处于一个五子棋匹配队列或一个五子棋房间。

### 2.3 五子棋房间

- 房间为双人房间。
- 房间连接路径包含 `gameCode` 与 `roomId`。
- 双方进入房间后服务端推送 `roomReady`，包含：
  - 房间 ID。
  - 本方用户 ID。
  - 对手用户 ID。
  - 黑白棋身份。
  - 先手方。
- 支持标准 15x15 棋盘。
- 服务端维护权威棋盘与胜负判定。
- 客户端只负责展示与提交落子请求，不得决定胜负。
- 支持以下房间事件：
  - 准备完成。
  - 落子。
  - 胜负结算。
  - 认输。
  - 断线判负或进入短暂重连窗口。
  - 房间释放。

### 2.4 战绩与积分

- 五子棋使用独立战绩表，不直接复用论坛积分账户。
- 初始五子棋积分建议为 1000。
- 一期积分规则采用简单胜负增减：
  - 胜方 +10。
  - 负方 -10，最低不低于 0。
- 记录每局对战结果：
  - 游戏编码。
  - 房间 ID。
  - 黑方、白方。
  - 胜方、负方。
  - 结束原因：五连、认输、断线、超时、系统关闭。
  - 开始时间、结束时间。
- 后续可扩展 ELO、段位、排行榜赛季。

## 3. WebSocket 分层规则

### 3.1 连接路径

一期建议路径：

```text
/ws/game-center/lobby?token=xxx
/ws/games/gobang?token=xxx
/ws/games/gobang/rooms/{roomId}?token=xxx
```

- 全部复用论坛 JWT 握手鉴权。
- 连接建立后从 `attributes` 读取 `userId` 和 `username`。
- 不使用 `HttpSessionHandshakeInterceptor`，因为论坛当前用户态基于 JWT。

### 3.2 连接隔离

- 不能复用现有 `OnlineUserManageUtil` 的 `userId -> WebSocketSession` 单连接表。
- 游戏连接需要按通道分表维护：
  - 大厅：`userId -> lobbySession`。
  - 游戏：`gameCode + userId -> gameSession`。
  - 房间：`roomId + userId -> roomSession`。
- 通知连接 `/ws/notify` 与游戏连接互不覆盖。

### 3.3 多开策略

- 同一用户可以同时保持：
  - 1 条 `/ws/notify`。
  - 1 条游戏中心大厅连接。
  - 1 条当前游戏连接。
  - 1 条当前房间连接。
- 同一用户同一通道重复连接时，一期采用“新连接覆盖旧连接，旧连接关闭”的策略。
- 同一用户不得同时匹配多个五子棋对局。
- 同一用户不得同时进入多个五子棋房间。

### 3.4 心跳与死连接

- 前端每 30 秒发送 `ping`。
- 服务端返回 `pong`。
- 服务端 90 秒未收到心跳则关闭连接并清理注册表。
- 房间断线后的处理：
  - 一期建议给 60 秒重连窗口。
  - 超过窗口未回到同一房间则判负。
  - 若双方同时断线，房间标记异常结束，不结算积分或按后续规则处理。

## 4. 五子棋核心规则

- 棋盘大小：15x15。
- 两名玩家分别执黑、白。
- 黑方先手。
- 玩家只能在自己回合落子。
- 落子坐标必须在棋盘范围内。
- 已有棋子的位置不能重复落子。
- 横、竖、主对角线、副对角线任一方向连续 5 子即胜。
- 一期不实现禁手、三三、四四等专业规则。
- 一期不实现观战、聊天、悔棋、复盘、AI 对战。

## 5. 与 gobang-demo 的关系

可迁移能力：

- `MatchAPI` 的开始匹配、取消匹配消息语义。
- `Matcher` 的按积分分段匹配思路。
- `RoomManger` 的 `roomId -> Room`、`userId -> roomId` 映射。
- `Room` 的 15x15 棋盘、五连检测、胜负推送逻辑。
- `game_hall.html` 与 `game_room.html` 的交互状态可作为 UI 原型参考。

需要改造的地方：

- demo 使用 HttpSession，论坛必须改为 JWT 握手。
- demo 只有匹配和房间两层连接，论坛需要大厅、游戏、房间三层连接。
- demo 用户表与论坛用户表不同，需接入论坛 `user` 与独立游戏资料表。
- demo 的房间和匹配均在 JVM 内存中，多实例部署需要明确粘滞策略或 Redis 协调。
- demo 的匹配队列线程与通知逻辑需要重写为可停止、可测试、线程安全的 Spring 服务。
