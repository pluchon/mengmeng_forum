# 未完成功能与技术债总览

> 归档日期：2026-07-14
> 优先级仍遵守 P0 → P1 → P2。这里记录尚未实现、只完成部分代码、尚未联调或已经暂缓的内容，不代表全部都要立即开发。

## 1. P0：成长中心必须收口的缺口

### 1.1 非正式用户严格只读权限

- 目前正式用户校验只覆盖部分帖子和问答写操作，尚未覆盖评论/楼中楼、弹幕、漂流瓶、私信/群聊、游戏匹配与房间聊天等所有写入口。
- 后端需要在各业务 Service 写入口统一校验认证上下文中的正式用户状态；前端需要同步隐藏或禁用写入口并给出成长中心引导。
- 需要补齐“非正式用户被拒绝、正式用户可正常操作”的跨模块权限回归测试。

### 1.2 体验会员资格与权益隔离

- 付费会员是否允许参加会员体验挑战、是否禁止覆盖或叠加付费权益，尚未形成完整校验闭环。
- `TRIAL_900` 体验会员所需的独立、缩减模型额度仍未接入实际配额/计费链路，当前不能等同于正式 900 档会员的完整模型用量。
- 成长中心尚需明确展示体验资格、已领取状态、有效期和剩余天数。
- 需要补充付费会员拒绝领取、重复领取、到期失效、体验额度耗尽等自动化测试。

## 2. P0/P1：社区产品路线

### 2.1 学习路径 P0

- 用户创建公开学习路径，配置标题、简介、封面和所属板块。
- 路径按顺序引用公开帖子或可用题目资源，支持作者排序、编辑和移除。
- 路径详情展示目录、当前进度和下一项；用户完成状态私有保存。
- 被引用内容删除、下线或无权限时需要安全降级，并可在个人主页展示用户创建的路径。

### 2.2 社区项目共创 P0

- 项目创建与浏览、角色和人数上限、招募/进行中/完成/归档状态。
- 申请加入、创建者审批或拒绝、成员权限和退出规则。
- 复用现有群聊作为项目沟通空间，并支持进度帖和成果链接。

### 2.3 问答增强 P1/P2

- 积分悬赏：冻结、采纳结算、关闭退款、幂等和争议处理。
- 楼主撤销最佳答案及相应状态规则。
- 回答质量排序、相似问题推荐和问答运营指标。

### 2.4 弹幕增强 P1/P2

- P1：弹幕位置/模式、有限字号、类型过滤、密度控制和基础治理增强。
- P2：轻量关键词过滤、播放顺滑优化和“我的弹幕”。

## 3. 游戏中心未完成项

- 游戏中心 Plus 的 Redis 匹配、房间快照和 Pub/Sub 尚未完成双实例联调与故障恢复验证。
- 远端 `game_finished` 状态仍需按本地用户视角重新拉取或个性化。
- Python AI 的完整联调、超时/降级策略和前端实时状态/UI 联调仍未封板。
- MQ 消费后的站内通知、统计刷新、排行榜刷新、棋谱生成等业务副作用尚未全部接入。

## 4. AI 目标架构未完成项

- 统一 AI Gateway、AiRuntime、Tool Registry 和 Java→Python 请求协议。
- 将已有审核能力收敛为公共 `ContentModerationGraph`，并补齐结构化输出和稳定降级。
- 帖子创作、帖子总结、搜索/RAG、游戏和看板娘等业务图仍需按统一运行时逐步迁移。
- 长任务状态、统一流式事件协议、断线恢复、工具调用审计、多模型策略和专家子图尚未完整落地。
- AI 模块不属于当前社区演进 P0，开发时必须单独立项，不能影响社区核心链路。

## 5. 并发、可靠性与性能待办

### 5.1 P1 补强

- 点赞/取消、评论删除、关注、收藏、签到、抽奖、VIP、积分和游戏结算的 20 并发自动化用例。
- 帖子回复通知等更多强追踪链路接入 Outbox/MQ 本地消息表。
- Outbox 消费状态、重试、死信和运营补偿治理。
- 补齐计数字段校准范围和 Micrometer 关键指标。
- AI 流式请求的主动停止、断网和重复计费边界。

### 5.2 P2 长期治理

- 高历史量列表的游标分页和深分页治理。
- 搜索、向量召回、画像、标签语义与弹幕桶缓存的性能专项。
- 仅在监控或压测证明存在瓶颈时，按高频接口逐个处理 N+1、批量查询和索引问题，禁止无证据的大范围 SQL 重写。

## 6. Java 后端规范债

- 组合 VO 仍存在直接嵌套 Entity 的位置，需要按帖子、私信、回复等模块逐步替换。
- 部分 Service 仍用 `Map` 作为业务载荷，需要改为独立 DTO/VO。
- `AiAuditUtils` 等位置仍有静态创建 HTTP 客户端的遗留写法。
- Session/登录校验样板、验证码业务下沉、登录接口返回类型、依赖注入、converter 和自动化测试仍需分模块治理。
- 这些整改必须保持 `Controller → Service → Mapper`、Lambda API、事务和认证上下文规则，不得借清理改变业务行为。

## 7. Vue 前端规范债

- 仍有组件未完全拆分为 `.vue` / `.js` / `.scss` 三文件。
- 部分页面仍缺少完整的加载中、错误、无权限、空数据四态。
- 业务状态魔法数字、分页结果解包、危险操作二次确认、提交禁用和后端 VO 契约仍需逐模块统一。
- 后续每批修改必须运行 `npm run build`，并对认证、权限、发帖、评论和支付/会员等核心流程做回归评估。
